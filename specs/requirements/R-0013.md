## 목표

여러 항목의 이름을 규칙으로 한꺼번에 바꾸되, 잘못되면 한 번에 원래대로 돌아갈 수 있게 한다.

## 요구 항목

- R-0013.1: 사용자는 선택한 여러 항목에 이름 규칙(예: 앞·뒤에 글자 붙이기, 글자 찾아 바꾸기·지우기, 번호 매기기)을 지정해 한꺼번에 이름을 바꿀 수 있다.
- R-0013.2: 사용자는 실행 전에 항목마다 원래 이름과 바뀔 이름을 미리 볼 수 있다.
- R-0013.3: 미리 보기에서 바뀐 뒤 이름이 서로 겹치거나, 같은 폴더의 다른 항목과 겹치거나, 쓸 수 없는 이름(금지 글자·예약 이름·끝의 점·공백·빈 이름·너무 김)이면 그 항목과 까닭이 보이고 실행할 수 없다.
- R-0013.4: 실행은 전부 바꾸거나 아무것도 바꾸지 않는다: 중간에 실패하면 이미 바꾼 항목을 원래 이름으로 되돌려 일부만 바뀐 채 멈추지 않는다.
- R-0013.5: 항목끼리 이름을 맞바꾸거나 한 항목의 새 이름이 다른 항목의 원래 이름과 같아지는 경우(예: 번호 밀기)도 겹침 없이 바뀐다.
- R-0013.6: 한꺼번에 바꾼 일은 작업 기록에 한 건으로 남고, 실행취소 한 번으로 모든 항목이 원래 이름으로 돌아가며 다시 실행도 한 번에 된다.
- R-0013.7: 규칙이 이름을 바꾸지 않는 항목은 건너뛰고 건너뛴 수를 알 수 있다.
- R-0013.8: 일괄 이름바꾸기는 명령 하나(명령 팔레트와 오른쪽 항목 메뉴에서 닿음)이고 두 항목 이상 선택했을 때 켜진다. 항목 메뉴에서는 「이름 바꾸기」 바로 아래 「일괄 이름 바꾸기」 한 줄(16줄)이다.
- R-0013.9: 검색 결과 위치처럼 항목이 여러 폴더에 있어도 항목마다 제 폴더에서 바뀐다.
- R-0013.10: 실행은 작업 대기열의 작업(`JobKind::BatchRename`)으로 돌아 작업 영역에 진행(항목 수)과 취소가 보이고, 취소하거나 중간에 실패하면 이미 바꾼 항목을 모두 되돌린 뒤 끝난다.

## 제약

- 명령은 통로와 무관하게 하나다(GLOSSARY의 명령). 실행은 `App::execute` 길을 쓴다.
- ADR-0005: 파일 작업은 facet 자체 엔진(`file_ops::rename`)으로 한다. 이름 확인은 `validate_name`을 그대로 쓴다.
- ADR-0007: 코어에는 화면 문장이 없고 이름·까닭 글자는 앱의 `text.rs`와 `@tr()`에 둔다. 규칙 계산·겹침 판정은 화면과 파일 시스템을 부르지 않는 순수 함수로 둔다.
- 작업 기록(`History`)의 100개 상한과 되돌릴 수 없는 기록 규칙을 따른다. 이 일은 되돌릴 수 있다.
- 속도: 선택 1만 개에서 미리 보기 계산이 한 프레임(16ms) 안(로컬 기준, CI는 10배 상한, 벤치마크로 지킨다).
- 한글 입력란이 생기면 `docs/ime-checklist.md`, 화면 확인은 사람 확인 목록을 갱신한다.

## 노드가 정한 것

- 규칙의 종류는 붙이기·찾아 바꾸기(글자 일치, 대소문자 무시)·번호 매기기로 읽었다: 문서가 든 세 예(날짜·꼬리말 지우기·번호)를 덮는 가장 작은 집합이고, 정규식·날짜 서식 등은 뒤에 더할 수 있어서.
- 사진에 날짜 붙이기는 사용자가 날짜 글자를 붙이기 규칙으로 직접 넣는 것으로 읽었다(항목 날짜를 읽는 규칙은 스펙이 필요하면 정함): 요구가 「날짜를 붙인다」일 뿐 날짜의 출처를 정하지 않아서.
- 전부 아니면 전무는 실행 중 실패 시 롤백으로 읽었다: 문서가 「일부만 바뀐 채 멈춤」을 위험으로 꼽았기 때문이다.
- 새 상시 화면 요소는 만들지 않는다: 오른쪽 메뉴·팔레트만.
- 다른 폴더 항목 간 번호는 선택 순서(목록 순서) 하나로 이어 매긴다.
- 오른쪽 메뉴 자리와 실행 표시는 이슈 댓글의 대표 답(2026-11-17)으로 확정했다: 항목 메뉴의 「이름 바꾸기」 아래 한 줄(빈 곳 메뉴와 `context_click` 동작은 바꾸지 않음), 실행은 작업 대기열의 `JobKind::BatchRename`. 항목 메뉴를 15줄로 못박은 기존 스펙 `mouse-reachable-commands`의 AC-6과 `item_menu_is_unchanged`, `tests/menu.rs`의 순서 단언은 Odin이 함께 새 순서로 고친다.
- 규칙은 한 창에서 찾아 바꾸기 → 앞·뒤 붙이기 → 번호 순으로 함께 적용하고(쓰지 않을 규칙은 비움) 파일은 확장자 앞까지만 바꾼다: 이슈 댓글의 노드 제안을 대표가 그대로 두었다.
- 검색 결과처럼 같은 폴더의 다른 항목을 다 모르는 곳은 실행 직전에 디스크에서 겹침을 확인해 막는다: 그 폴더의 목록을 모르기 때문이다.

## 범위 밖

- 정규식 이름 규칙, 내용·메타데이터(EXIF 등) 기반 이름.
- 확장자 변경 규칙과 폴더 이동을 겸하는 바꾸기.
- 규칙 프리셋 저장.
- 탐색기 F2 기본 동작 변경.
- 빈 곳 메뉴에 일괄 이름바꾸기를 두는 것.
