# 한글 IME 체크리스트

facet의 이름 입력란(F2)에서 한글 입력이 되는지 사람이 Windows 기계에서 확인하는 목록이다. 화면은 자동 테스트하지 않으므로(spec #1의 Testing Decisions) 이 목록이 유일한 확인 수단이다. Slint나 입력 처리 코드를 바꾼 뒤, 그리고 spec이 끝날 때마다 다시 확인한다.

## 준비

1. Windows 설정에서 한국어 입력기(Microsoft 입력기, 두벌식)를 켠다.
2. 시험 폴더를 만들고 앱을 연다.

   ```
   cargo xtask test-folder
   cargo run --release -p facet-app -- %TEMP%\facet-test-folders\items-100000
   ```

   작은 폴더면 아무 폴더나 괜찮다(`cargo run -p facet-app -- <폴더 경로>`).
3. 목록에서 항목 하나를 고르고 F2를 누른다. 그 행의 이름 자리에 현재 이름이 채워진 입력란이 뜬다(파일은 확장자 앞까지, 폴더는 전체가 선택됨).

이름 입력란은 **실제 파일 이름을 바꾼다**(#156). Enter나 입력란 밖 클릭으로 확정하면 디스크의 이름이 바뀌고 목록에 새 이름이 선택된 채 보인다. Esc는 입력을 취소하고 이름은 그대로다. 시험은 지워도 되는 작은 폴더(예: `%TEMP%acet-ime`)에 파일·폴더를 몇 개 만들어 그 안에서 한다.

## 확인할 것

각 항목을 한 번씩 하고 결과(통과/실패와 본 것)를 적는다. 한 항목이 끝나면 Esc나 Enter로 입력란을 닫고 F2로 다시 연다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 1 | 두벌식으로 「새 폴더 가나다」 입력 | 조합 중인 글자가 입력 위치에 보인다. Enter 뒤 목록의 이름이 「새 폴더 가나다」로 바뀐다 |
| 2 | 「가나다」를 치다가 「다」를 조합하는 중에 Enter | 글자가 한 번만 확정된다(이름이 「가나다」, 「가나다다」가 아니다) |
| 3 | 조합하는 중에 Esc | 입력이 취소되고 남은 글자가 없다. 입력란이 닫히고 목록의 이름은 원래대로다. F2로 다시 열면 원래 이름이 채워져 있다 |
| 4 | 조합하는 중에 ←·→ 방향키, 또는 입력란 안의 다른 위치를 마우스로 클릭 | 조합하던 글자가 확정되고 커서가 옮겨진다. 목록의 선택은 움직이지 않는다 |
| 5 | 한글 한 글자(예: 「한」)를 치고 한자 키 | 한자 후보 창이 입력 위치 근처에 뜨고, 후보를 고르면 그 한자로 바뀐다 |
| 6 | 한/영 키로 영문으로 바꾼 뒤 `New folder` 입력 | 영문이 정상으로 들어가고 남은 한글 조합이 없다 |

## 이름 확정과 새 폴더(#156)

이름 입력란이 실제 이름바꾸기에 이어진 뒤의 확인이다. 확장자 있는 파일(예: 「메모.txt」) 하나와 폴더 하나를 둔다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 19 | 「메모.txt」에서 F2, 두벌식으로 「가나」를 조합하는 중에 Enter | 「가나」가 한 번만 들어가 「가나.txt」로 바뀌고 그 항목이 선택된 채 보인다. 확장자 확인을 묻지 않는다(확장자 앞만 선택돼 있었다) |
| 20 | F2로 전체를 지우고 「다」를 조합하는 중에 Esc | 입력이 취소되고 이름은 그대로다. 조합하던 글자가 어디에도 남지 않는다 |
| 21 | F2로 이름 끝에 「라」를 조합하는 중에 다른 행을 클릭 | 조합하던 글자가 확정된 이름으로 바뀌고(한 번만) 누른 행이 선택된다 |
| 22 | F2로 확장자까지 지우고 「바」를 조합하는 중에 Enter | 「확장자를 바꾸면…」 확인이 입력란 곁에 뜨고 이름은 아직 그대로다. 다시 Enter(예)면 바뀌고, Esc(아니오)면 입력란으로 돌아가 「바」가 남아 있다 |
| 23 | 이름에 `?`를 치거나 「CON」을 친다 | 입력란 곁에 까닭(어떤 글자인지, 예약 이름)이 빨갛게 보이고 Enter가 확정하지 않는다 |
| 24 | Ctrl+Shift+N 뒤 곧바로 「자료」를 두벌식으로 친다 | 「새 폴더」(있으면 「새 폴더 (2)」) 행에 이름 전체가 선택된 입력란이 열려 있어 「자료」로 바뀌고, 조합 중 Enter면 「자료」 폴더가 한 번만 확정된다 |
| 25 | Ctrl+Shift+N 뒤 「가」를 조합하는 중에 Esc | 입력이 취소되고 「새 폴더」로 남는다 |
| 26 | 입력란에서 몇 글자 친 뒤 Ctrl+Z | 입력란의 글자 편집만 되돌린다. 작업 영역에 「실행취소」가 생기지 않는다 |

## 한글 모드의 단축키

단축키는 입력한 글자가 아니라 키로 맞춘다(코어 `facet_core::command`, #56). 한글 모드에서 H 키는 「ㅗ」를 내지만 Ctrl+H는 영문 모드와 똑같이 동작해야 한다. 키 이벤트 수준은 `crates/facet-core/tests/command.rs`가 확인하고, 실제 IME는 사람이 아래를 본다. 앱이 단축키를 코어의 명령 목록으로 실행하게 된 뒤(#58, #60) 확인한다. 입력란이 닫힌 상태(목록에 키보드 입력이 있는 상태)에서 한/영 키로 한글 모드로 바꾸고 누른다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 7 | 한글 모드에서 Ctrl+H | 숨김 항목 보이기/감추기가 바뀐다(영문 모드와 같다). 목록에 「ㅗ」가 들어가거나 글자로 이동이 일어나지 않는다 |
| 8 | 한글 모드에서 Ctrl+L, Alt+D | 주소창이 고쳐 쓰는 모드가 되고 전체 경로가 선택된다 |
| 9 | 한글 모드에서 Ctrl+Shift+P | 명령 팔레트가 열린다 |
| 10 | 한글 모드에서 Ctrl+A | 모든 항목이 선택된다 |

## 글자로 이동

목록에 키보드 입력이 있는 상태(입력란이 닫힘)에서 한글 모드로 친다. 앱은 보이지 않는 입력란으로 키를 받아, IME가 조합을 끝낸 글자만 코어의 글자로 이동(`Tab::type_to_select`)에 넘긴다(#58). 한글 이름 항목(예: 「가나.txt」, 「나비.txt」, 「다리.txt」)이 있는 폴더에서 확인한다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 11 | 한글 모드에서 「나」를 치고 다음 글자(예: 스페이스나 다른 자음)로 조합을 끝낸다 | 「나」로 시작하는 항목에 커서가 가고 그 항목이 선택된다. 조합 중인 글자가 화면 어디에도 남지 않는다 |
| 12 | 한글 모드에서 「나비」를 1초 안에 이어 친다 | 「나비」로 시작하는 항목으로 간다 |
| 13 | 한글 모드에서 같은 글자를 거듭 친다 | 그 글자로 시작하는 항목을 차례로 돈다 |
| 14 | 한글 모드에서 Enter·Backspace·↑↓ | 열기·뒤로·커서 이동이 영문 모드와 같다 |

## 함께 볼 것

- 입력란이 열린 동안 ↑↓·Page Up/Down·Home/End가 목록을 움직이지 않는다.
- 입력란이 열린 동안 다른 행을 클릭하면 입력이 확정되고(이름이 바뀐다) 그 행이 선택된다. 막힌 이름이면 확정하지 않고 입력란이 남는다.
- Esc로 취소한 경우에는 파일 이름이 바뀌지 않는다(탐색기로 확인).

## 주소창

주소창을 글자로 고쳐 쓰는 모드(#59)도 같은 TextInput 방식이다. 한글 이름 폴더(예: `%TEMP%\facet-한글\가나다`)를 만들어 두고 확인한다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 15 | Ctrl+L로 고쳐 쓰는 모드를 열고 끝에 `\가`를 두벌식으로 친다 | 조합 중인 글자가 입력란에 보이고, 조합이 끝나면 「가」로 시작하는 하위 폴더 후보가 아래에 뜬다 |
| 16 | 「가나다」를 조합하는 중에 Enter | 글자가 한 번만 확정되고 그 폴더로 간다(「가나다다」가 아니다) |
| 17 | 조합하는 중에 Esc | 경로 조각 모드로 돌아가고 남은 글자가 없다. 탭은 원래 위치다 |
| 18 | 한글 모드에서 Alt+D, F4 | 고쳐 쓰는 모드가 되고 전체 경로가 선택된다 |

## 필터 입력란

필터 입력란(Ctrl+Shift+F, #203)도 같은 TextInput 방식이다. 한글 이름 항목(예: 「보고서.txt」, 「보관함」, 「가나.txt」)이 있는 폴더에서 확인한다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 19 | Ctrl+Shift+F(한글 모드에서도) | 활성 패널의 주소창 아래에 필터 입력란이 열리고 포커스를 받는다 |
| 20 | 한글 모드에서 「보」를 치고 이어 「고」를 조합한다 | 조합 중인 글자가 입력란에 보인다. 조합이 끝난 글자까지 반영해 목록이 좁혀진다 |
| 21 | 필터 중 상태 표시줄 | 「n / 전체 m 항목」(n: 보이는 수, m: 필터 없이 보일 전체 수)으로 보인다. 선택 수는 보이는 항목만 센다 |
| 22 | 조합하는 중에 Esc | 필터가 지워지고 원래 목록이 돌아오며 입력란이 닫히고 키보드가 목록으로 간다. 남은 글자가 없다 |
| 23 | 입력란 안에서 Ctrl+Z | 글자 편집만 되돌린다(작업 실행취소가 아니다) |
| 24 | 필터를 건 채 폴더로 들어가거나 뒤로·위로·주소창으로 간다 | 필터가 풀리고 입력란이 닫힌다 |
| 25 | 탭 A에 필터를 걸고 탭 B로 갔다가 돌아온다 | 탭마다 필터가 따로다: A는 그 글자가 든 입력란과 좁혀진 목록이고 B는 필터가 없다 |

## 일괄 이름 바꾸기 입력란

일괄 이름 바꾸기 창(항목 둘 이상을 고르고 명령 팔레트의 「일괄 이름 바꾸기」나 오른쪽 메뉴)의 입력란(찾을 글자, 바꿀 글자, 앞에 붙일 글자, 뒤에 붙일 글자, 시작 번호, 자릿수, 구분 글자)도 같은 TextInput 방식이다. 한글 이름 파일 여럿이 든 폴더에서 확인한다.

| # | 할 일 | 기대 결과 |
| - | ----- | --------- |
| 26 | 항목 셋 이상을 고르고 「일괄 이름 바꾸기」를 연다 | 창이 열리고 「찾을 글자」가 포커스를 받으며 모든 줄이 흐리고 「바꿈 0 · 건너뜀 n · 문제 0」이며 「바꾸기」가 꺼져 있다 |
| 27 | 각 입력란에서 한글 모드로 「사」를 치고 이어 「진」을 조합한다 | 조합 중인 글자가 입력란에 보인다. 조합이 끝난 글자로 목록의 바뀔 이름이 바뀐다(앞에 붙일 글자면 「사진이름.txt」, 확장자는 그대로) |
| 28 | 입력란에서 Enter | 문제가 없고 바꿀 것이 있으면 창이 닫히고 작업이 시작된다. 아니면 아무것도 하지 않는다 |
| 29 | 입력란 안에서 Esc | 아무것도 바꾸지 않고 창이 닫힌다 |
| 30 | 입력란 안에서 Ctrl+Z | 글자 편집만 되돌린다(작업 실행취소가 아니다) |
